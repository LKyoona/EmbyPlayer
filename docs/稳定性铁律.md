# EmbyRemotePlayer 稳定性铁律

> 2026-09-11 播放全挂事故的完整复盘。四层 bug 叠加导致"一切正常但就是不能播"。
> 以后改代码前先过一遍这里，别让历史重演。

## 事故时间线（4 层叠加）

| 层 | 症状 | 根因 | 修复 |
|---|---|---|---|
| 数据层 | 库列表全是点不开的死卡片 | hijack 站每部未刮削电影存两份：真 `Movie` + `Folder` 壳。壳的 Children=404、PlaybackInfo=410 | `GetItemsAsync` 改 `Recursive=true + IncludeItemTypes=Movie,Series`，加 `GetPlayableChildrenAsync` 下钻 |
| 逻辑层 | Hero"立即播放"对壳条目直接抛异常 | `StartPlaybackAsync` 假设传入条目永远 CanPlay | 加 `ResolvePlayableItemAsync`：非 CanPlay 先解析成真实视频再协商 |
| 传输层 | VLC 永远卡在 Opening | `:http-continuous` 与 nginx 边缘互斥，长连接被掐 | 删除该选项，`:http-reconnect` 已够 |
| 身份层 | 流秒断（Ended, pos=0ms） | `ApplyMediaHttpHeaders` 默认注入 `Mozilla/5.0` 浏览器 UA，边缘按 UA 拒流 | 仅媒体源 `RequiredHttpHeaders` 明确要求时才注入 UA/Referer |

另有一条线路层结论：**HK CDN（cdn-hk.longemby.com）掐 VLC 的 TLS 指纹**（`Interrupted function call`），cf 线兼容。播放优先走 cf。

## 铁律（改代码前必读）

### 1. 条目类型：永远不要假设拿到的是能播的

- 列表接口返回的任何条目都可能是 `Folder`/`Series`/`BoxSet`，**`CanPlay=false` 是常态而非异常**。
- 任何通往 `CreatePlaybackPlanAsync` 的路径，入口处必须检查 `item.CanPlay`，不能播就走 `ResolvePlayableItemAsync` 下钻。
- **禁止**新建绕过 `StartPlaybackAsync` 的播放入口。所有播放必须过统一入口。

### 2. 查询：对 hijack 站只信 typed query

- 列文件夹用 `Recursive=false` 的裸查询会被 `Folder` 壳淹没。
- 带条目类型的递归查询（`IncludeItemTypes=Movie,Series`）是唯一稳定形状。
- 服务器对这个站还有个怪癖：`Users/{uid}/Items?ParentId=<壳id>` 会 404，**别依赖 Children 端点**。

### 3. VLC 选项：加任何新 option 前先跑矩阵测试

- `:http-continuous` 是历史教训——单加一个选项就能让所有播放死在 Opening。
- 改 `StartMedia` 的 option 列表前，先用最小可复现程序（`/tmp/embytest` 模式）做逐项排除测试。
- `Media` 构造统一用 `new Media(libvlc, uri.AbsoluteUri, FromType.FromLocation)`，**禁止** Uri 重载（会走 UNC 形态）。

### 4. HTTP 身份：永远不伪装浏览器

- 边缘按 UA 白名单放行：`Emby/*`、VLC 默认 UA 放；`Mozilla/5.0` 开头的一律拒/断流。
- 这是站方规则（"禁止浏览器播放"），不是 bug，**不要试图绕过**。
- UA/Referer/Cookie 只在 `MediaSource.RequiredHttpHeaders` 明确要求时注入（signed strm 场景）。

### 5. 线路：cf 为主，HK 不做直连

- cf 线（`cf.longemby.com`）：VLC 直连已验证 4K HEVC OK，是默认线。
- HK 线（`cdn-hk.longemby.com`）：API 全通，但 VLC 直连被 TLS 指纹拦截。**除非实现 HLS 转码模式，否则不切换**。
- 加新线路时，先用 HttpClient probe + VLC 实播双重验证，缺一不可。

### 6. 验证流程：改完必须过四关

```
1. dotnet build 0 警告 0 错误
2. 独立链路测试（登录→列表→plan→probe 206）
3. VLC 实播测试（Playing 状态 + pos 持续 >0ms 推进）
4. 真机跑一遍（冷启动、换线、4K HEVC 片源）
```

- "probe 206 但 VLC 打不开"是合法状态——说明问题在 VLC 层，别在协商层绕圈。
- VLC 报 `Could not open \\host\path` = 走了文件层没走网络层，查 Media 构造。
- VLC 报 `Ended pos=0ms` = 服务器秒断流，先查 UA/头注入，再查签名过期。

### 7. 调试资源

- 应用日志：`%LOCALAPPDATA%\EmbyRemotePlayer\logs\app-YYYYMMDD.log`
- LibVLC 日志已接入 `LogService`（含 sig/token 脱敏），报错先看这里再猜。
- 诊断探针：`F12 网络控制台` 的 "Media health probe" 能区分服务器故障 vs 本地解码故障。

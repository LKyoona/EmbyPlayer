# EmbyRemotePlayer 核心架构与技术设计文档

本文档全面梳理 EmbyRemotePlayer 的系统架构、核心管线与交互设计规范，作为系统技术基线文档。

---

## 一、 整体分层架构

系统严格遵循分层解耦与职责隔离原则：

### 1. UI 呈现与交互层（Views & ViewModels）
- **`MainWindow`**：负责主界面路由、媒体库导航栈（`BrowseSnapshot`）、纵向与横向滚动视口计算以及顶层内容聚合。
- **`MediaCardViewModel`**：承载卡片展示数据与视口加载状态位（`IsImageLoaded`），隔离视口重复调度。
- **`HomeRowViewModel`**：平台级首页动态内容行调度（Hero 看板、接着看、继续观看、个性化推荐、最新入库等）。
- **`PlayerWindow`**：承载 LibVLC 原生渲染窗口句柄（HWND）、硬件解码通道以及多媒体流生命周期。
- **`PlayerViewModel`**：纯粹的 MVVM 状态机与命令中心，驱动播放控制栏、时间轴进度、音量调节与交互防抖。

### 2. 核心服务层（Services）
- **`EmbyApiClient`**：轻量级元数据抓取、播放协商（`PlaybackInfo`）、直接播放与 HLS 转码流地址构建、心跳进度上报。
- **`ApiResponseCacheService`**：二级元数据缓存中心（内存强类型热缓存 + 磁盘二进制缓存），支持 Stale-While-Revalidate（边读旧值边在后台刷新）。
- **`ImageCacheService`**：视口优先级调度队列、并发下载合并（Request Coalescing）、固定尺寸桶归一化、解码并发隔离与有界双层 LRU 缓存。
- **`EmbyEventSocketService`**：WebSocket 实时长连接，接收服务器端变更推送，精准触发缓存过期。
- **`NetworkDebugService`**：按需捕获网络审计日志，提供 F12 开发者控制台支持。
- **`ProfileStore`** & **`CredentialStore`**：基于 Windows DPAPI / Credential Manager 的凭据安全托管与原子文件配置落盘。
- **`LogService`**：全局滚动日志，包含敏感信息（Token / 签名密钥）动态脱敏。

## 二、 视口驱动的图片管线（Image Pipeline）

传统的媒体客户端在列表接口返回百条数据时往往直接并发拉取百张图片，导致网络与 UI 线程瞬时阻塞。本项目采用严格的**视口优先调度流水线**：

### 1. 元数据与图片分离
媒体库列表接口仅拉取卡片必要字段，不提前下发多版本信息，更不会触发图片的无节制预加载。

### 2. 动态视口规划器（Viewport Planner）
`MainWindow` 根据当前的滚动偏移量与窗口物理高度，动态计算可视元素：
- **`Immediate`**：详情页背景 Hero 大图、封面大图，最高优先级直发；
- **`Visible`**：当前视口内可见的卡片图片；
- **`Prefetch`**：视口外短距离预取窗口（下一小屏内容）。
页面离开或关闭时，自动取消当前视口内正在等待的全部预取任务，绝不让离开的页面占用带宽。

### 3. 尺寸桶归一化（Width Bucketing）
所有请求按目标宽度强行归一到 4 级尺寸桶：
`256px` | `512px` | `1024px` | `1600px`
避免因前端组件尺寸微调（例如 220px 与 300px）向服务端发起近乎重复的裁切请求，大幅提升本地缓存复用率。

### 4. 请求合并与动态提权（Request Coalescing）
- 缓存键由 `Server + ItemId + ImageType + Tag + BucketWidth` 构成；
- 采用并发字典追踪正在进行的下载任务，相同请求只发起一次物理网络连接，下游多个消费者共享同一 Task；
- 预加载（`Prefetch`）项若因用户快速滚动进入可视区，自动原地升级为 `Visible` 高优先级。

### 5. 解码资源与网络并发双重隔离
- **网络层**：8 个后台工作线程分别消费 Immediate、Visible、Prefetch 队列；
- **解码层**：使用 `SemaphoreSlim(2, 2)` 严格将 WPF/WIC 位图解码并发数限制为 2；
- 在创建 `BitmapImage` 之前强制设定 `DecodePixelWidth`，杜绝解码全尺寸原图撑爆内存。

### 6. 有界双层缓存
- **内存 LRU**：上限约 220 MiB 解码后位图预算，超额按访问序列淘汰；
- **磁盘存储**：上限约 768 MiB，后台定期清理陈旧文件；
- 结合 Emby 服务端的 Image Tag，服务端海报更新后会自动生成新键，无需手动清除旧缓存。

## 三、 Stale-While-Revalidate 元数据缓存流水线

针对海量影视库卡顿问题，系统从 v0.7 起实施“缓存优先”架构：

1. **强类型内存优先**：先查内存缓存，命中后直接复用已反序列化的 C# 实体对象，连 JSON 解析都完全免除；
2. **本地磁盘二级缓存**：内存未命中则读取本地二进制缓存文件；
3. **极速直出与后台刷新**：若缓存仍在宽容期内，UI 立即拿旧数据渲染，后台悄然发起网络请求拉取最新数据，彻底消灭切换页面时的空白与等待圈；
4. **WebSocket 被动协同失效**：
   - 监听 Emby 的 `ClientWebSocket` 推送；
   - 收到 `LibraryChanged` 时，将元数据标记为 Stale（但保留旧快照以供即时渲染）；
   - 收到 `UserDataChanged` 时，仅将继续观看（Resume）和相关条目标记为 Stale；
5. **延时遮罩（180ms 规则）**：
   界面的加载中（Loading）遮罩统一延时 180ms 出现。缓存命中时页面在 10ms 内完成渲染，用户完全感知不到任何加载框闪烁。

## 四、 播放器架构与 MVVM 边界规范（`PlayerWindow` & `PlayerViewModel`）

### 1. 宿主与状态机的明确分工
- **`PlayerWindow`（控制层/宿主）**：
  负责 LibVLC 的 C++ 原生动态库句柄绑定、硬件解码器初始化、Windows 原生消息处理、全屏切换与物理屏幕边界对齐。
- **`PlayerViewModel`（表现层/状态机）**：
  拥有播放/暂停、快进/快退（±10s）、音量调节、静音、全屏切换、关闭、窗口最小化等一整套 `ICommand`，以及播放时间轴、缓冲进度、状态栏显隐状态。

### 2. 交互与防误触规则
- **3 秒无操作自动隐藏**：
  控制栏开启 3 秒倒计时自动隐去。当鼠标在控制条、滑块或选集抽屉上停留时，通过 `KeepVisibleCheck` 自动挂起计时器，绝不在用户操作时突然隐藏导致点击击穿到视频层造成误暂停。
- **时间轴几何唯一归属**：
  时间轴进度条由 WPF 的 `Track` 与 `Thumb` 唯一接管，拖动过程中不会被异步进度回写覆盖；松手（DragCompleted）后才向底层发起最终 Seek 指令。
- **真物理全屏（SetWindowPos）**：
  不使用可能受系统任务栏遮挡或窗口动画影响的普通 `Maximized` 模式，而是直接调用 Win32 API（`MonitorFromWindow` + `GetMonitorInfo`）提取显示器的真实物理边界 `rcMonitor`，临时剔除 `WindowChrome` 覆盖任务栏，退出全屏时无损恢复。

## 五、 流媒体播放协商与网络容灾

1. **直接播放优先与转码平滑降级（DirectPlay & Transcoding Fallback）**：
   优先尝试直连 DirectPlay。若在 16 秒内未观察到 LibVLC 进入正常 `Playing` 状态或出现解码器严重报错，系统自动平滑切换至服务端的 HLS 兼容转码流。
2. **带外连通性探针（ProbeMediaUriAsync）**：
   在正式打开流之前，可通过 HTTP Range 206 发起带外短探针，在毫秒级内甄别出是“服务端/CDN 断流拒绝”还是“本地 VLC 解码器故障”，并实时上报给 F12 诊断面板。
3. **网络身份合规**：
   遵循服务端防盗链与特定 CDN（如 LongEmby 系）的白名单准则，默认不伪装浏览器 UA，防止因伪装 `Mozilla/5.0` 导致边缘 CDN 节点主动断流。

## 六、 故障隔离原则

- **UI 导航防竞态**：所有页面跳转携带 `CancellationToken`，防止旧页面慢请求覆盖新页面的渲染结果。
- **浏览栈内存快照**：Browse 浏览页返回上一级完全依靠内存中的 `BrowseSnapshot` 快速恢复列表与滚动条位置，返回无需重新请求接口。
- **关键配置原子落盘**：所有配置文件（如多服务器凭据与配置）均先写入临时文件，成功后再通过系统级原子替换落盘，断电或意外退出不会导致配置损坏。

# 开发工作流：改完代码如何立即看到效果

适用于**任何人**（你自己手动改，或 AI 改完之后你来验收）。所有命令都在仓库根目录执行，也可以双击 `dev.cmd` 进菜单选。

## 30 秒速查

| 刚改了什么 | 命令 | 见效方式 |
|---|---|---|
| C# 方法内部的小改动 | `dev.ps1 watch`（挂着一个终端） | 保存文件即热应用，秒级，应用不重启 |
| XAML 样式 / 布局 / 大改动 | `dev.ps1 watch`，或 `dev.ps1 run` | watch 自动重编译，能热应用就热应用，否则自动重启；`run` 是全新启动 |
| 任何修改的稳妥路径 | `dev.ps1 run` | 增量编译（几秒）→ 启动最新代码 |
| 确认「用户拿到的包」 | `dev.ps1 verify` | 自动重新打包过期产物 + 完整性检查 + 8 秒冒烟启动 |

```text
powershell -ExecutionPolicy Bypass -File dev.ps1 watch    # 挂机实时开发
powershell -ExecutionPolicy Bypass -File dev.ps1 run      # 改一次跑一次
powershell -ExecutionPolicy Bypass -File dev.ps1 build    # 只编译不运行
powershell -ExecutionPolicy Bypass -File dev.ps1 pack     # 打包 + dist zip
powershell -ExecutionPolicy Bypass -File dev.ps1 verify   # 打包 + 验证一条龙
powershell -ExecutionPolicy Bypass -File dev.ps1 clean    # 清理构建产物
```

## 三个输出目录，先分清你跑的是哪个

| 目录 | 谁生成 | 说明 |
|---|---|---|
| `src\EmbyRemotePlayer\bin\Debug\` | `watch` | Debug 开发版，编译最快 |
| `src\EmbyRemotePlayer\bin\Release\` | `run` / `build` | Release 开发版 |
| `publish\win-x64\` | `pack` / `verify` | **自包含发布版 = 用户拿到的最终产物** |

> ⚠️ 最常见的假象：「我改了代码，怎么没效果？」——因为你双击的是 `publish\win-x64` 里的**旧 exe**，它不会因为源码修改而自动更新。改完代码要看发布版效果，必须重新 `pack`（或直接 `verify`，它会检测版本过期并自动重打包）。

## watch：保存即生效的挂机模式

原理是 `dotnet watch run`（Debug 配置）。启动后终端保持挂着，之后每次保存源文件：

1. 自动增量编译（几秒）
2. **能热应用的修改直接生效**，应用不关闭（典型：C# 方法体内部改逻辑、改字符串）
3. **无法热应用的修改（rude edit）自动重启应用**（典型：新增文件、改方法签名、大部分 XAML 结构变化）
4. 任何时候可按 **Ctrl+R** 强制重启应用、**Ctrl+C** 退出 watch（应用一起关闭）

实测注意事项：

- 热重载最适合「改现有方法里的代码」；结构性修改都会走自动重启，重启后 UI 状态（当前页面、登录态的内存部分）会重置，服务器令牌等持久化数据不受影响
- 偶发进程残留：如果发现旧窗口没关、新窗口又开了，任务管理器结束所有 `EmbyRemotePlayer` 进程后重新 `watch`
- watch 跑的是 Debug 配置。极少数情况 Debug/Release 行为不一致时，用 `run`（Release）交叉验证

## run：最可靠的一次一跑

`dev.ps1 run` = 先确保编译（有改动才重编，秒级）→ 启动 `bin\Release` 的全新进程。

**任何怀疑「刚才那个改动到底生效没有」的时刻，用 `run`**：全新进程加载的一定是磁盘上最新的程序集，没有热重载的不确定性。

## verify：发布视角的最终确认

`dev.ps1 verify` 做四件事：

1. **文件完整性**：主程序、`libvlc\win-x64` 原生库、文件数
2. **版本一致性**：exe 内嵌版本 = csproj `<Version>`；**publish 目录是旧版本时自动重新 pack**，所以 verify 永远验证的是最新代码
3. **分发 zip**：`dist\EmbyRemotePlayer-v<版本>-win-x64.zip` 存在且体积正常
4. **冒烟启动**：启动打包后的 exe 保持 8 秒确认不崩溃后自动关闭（屏幕闪一个窗口是正常现象；XAML 资源引用错误这类启动即崩的问题会被它抓住）

## 场景手册

### 你自己改代码

开一个终端挂 `watch`，编辑器里改完 Ctrl+S 直接看应用窗口；改完一批后想要干净状态就 Ctrl+C，再 `run` 或 `verify`。

### AI 改完代码，你要验收

AI 每次交付前都会跑过 `build`（多数时候还有 `verify`）。你只需要：

1. `git diff` 快速过一眼改动清单（可选）
2. `dev.ps1 run` 看运行效果；如果 AI 说明已 verify，也可以直接跑 `publish\win-x64\EmbyRemotePlayer.exe`
3. 满意就 commit；不满意把现象反馈回去

### 从 GitHub 拉取别人的修改

```text
git pull
dev.ps1 build     # 快速确认编译通过
dev.ps1 run       # 看效果
```

### 要发布新版本

1. 改 `src\EmbyRemotePlayer\EmbyRemotePlayer.csproj` 里的 `<Version>`
2. `dev.ps1 verify`（自动 pack + 全套检查）
3. `dist\` 里的 zip 就是可分发产物；推送到 GitHub 后 CI 也会自动构建并上传同名 artifact

## 问题排查

| 现象 | 原因与解法 |
|---|---|
| 改了没效果 | 先确认跑的是哪个目录的 exe（见上表）；`publish` 旧包要重新 `pack` |
| 旧实例干扰 | 任务管理器结束所有 `EmbyRemotePlayer` 进程再启动 |
| 构建报「未能复制/文件被占用」（MSB3021/3026） | 应用还开着占用了 exe → 关掉应用再试；仍不行 `dev.ps1 clean` 后重新 build |
| watch 热重载没反应 | Ctrl+R 重启应用，或 Ctrl+C 退出后改用 `run` |
| verify 失败：版本不一致 | 正常不会发生（verify 会自动重打包）；手动确认 csproj `<Version>` 与报错提示 |
| 中文显示乱码 | 用 `dev.cmd` 或 `powershell -File dev.ps1` 方式运行，不要把脚本内容粘贴到老式 cmd 窗口执行 |
